# VeriLedger webapp — backlog and sprint plan

Oct 20, 2026 · @Alessandro David

32 stories in 6 epics (E0 to E5). E0 records what was built on July 29, 2026, retroactively, so that the audit can check each criterion against a test; VLW-07 is the documentation of October 20. E1 to E4 come from the audit of the same day ([AUDIT.md](AUDIT.md)). E5 (VLW-27 to VLW-34) builds design direction E, chosen the same day ([ADR-0004](adr/0004-design-direction-e.md), [DESIGN.md](DESIGN.md)), and absorbs VLW-20; VLW-34 follows the API's ADR-0006 (visitors browse without an account and start a demo with one click). MoSCoW priority (M = Must, S = Should, C = Could) and estimate in points (1, 2, 3, 5, 8). IDs VLW-08, VLW-09 are left free.

**Redesign early, in order** (product owner, 2026-10-20). The redesign does not wait for the rest of the plan, and it does not run ahead of the API either:

- Sprint 1 builds design E's foundation (tokens, shell, login, states) on a repository that compiles, with tests and CI.
- Each view lands in the sprint where its data exists. The API brings its data endpoints forward to its Sprint 2.
- Deployment stays in Sprint 4.
- Pages that are about to be replaced are not cleaned up; their replacements follow the comment rules from the start.

The API's stories (VLA-NN) live in `veriledger-api/docs/BACKLOG.md`. Both backlogs use the same sprint numbers and dates; a story that needs its counterpart says so and merges after it.

## Sprint plan

Two-week sprints, the same as the API's. Each sprint closes with a demonstrable goal and its notes in `docs/sprints/sprint-N.md`.

| Sprint | Dates | Goal | Stories | Pts | Depends on (API) |
| --- | --- | --- | --- | --- | --- |
| 0 | Jul 29 – Oct 25, 2026 | Baseline as built, documented and audited | VLW-01 to 07 | 16 | — |
| 1 | Oct 26 – Nov 8 | Builds from a clean clone, with tests and CI, inside design E's shell and sign-in. Done on 2026-10-20 (#2 to #15) | VLW-10 to 14, 27, 33 | 14 | — |
| 2 | Nov 9 – 22 | The tower, and signing that works with keys that never leave the browser | VLW-15 to 18, 21, 22, 28, 30 | 22 | VLA-15, VLA-16, VLA-20, VLA-33 |
| 3 | Nov 23 – Dec 6 | Every other view in design E, open to visitors, and the production image | VLW-19, 29, 31, 32, 34 | 14 | VLA-19, VLA-34, VLA-35, VLA-36 |
| 4 | Dec 7 – 20 | End-to-end and accessibility checks, deployed with the API, released as 1.0.0 | VLW-23, 24, 25, 26 | 13 | VLA-27 |

**Order inside Sprint 1.** VLW-11 first (nothing else is green without it), then VLW-12, VLW-10, VLW-13, VLW-27, VLW-33, and VLW-14 last on the files that survive.

**Order inside Sprint 2.** VLW-15 and VLW-16 first (the signing library and local keys), then VLW-30 on top of them, VLW-18 once the API's nonce exists, VLW-17, and VLW-28 when VLA-20 and VLA-33 are merged.

**Buffer.** Sprints 2 and 3 carry 17 points each. If a sprint does not close, move out the "Should" stories (VLW-14, VLW-19, VLW-24, VLW-26, VLW-32) before cutting quality on a "Must". A view whose API data is late waits; it is never built on invented data (DESIGN.md).

**Design.** A view is done when it matches its artboard in the canvas (DESIGN.md) at 1280 and 360 px, with the same tokens and the same animations. A difference is fixed in the code or, if the design was wrong, in the artboard and DESIGN.md in the same PR.

**Minimum ceremonies.** Shared with the API: 30-minute planning, a 5-minute demo at the close, and a 3-line retrospective in each repository's `docs/sprints/sprint-N.md`.
