# Sprint 2 — The tower, and signing that works with keys that never leave the browser (VLW-15 to VLW-18, VLW-21, VLW-22, VLW-28, VLW-30)

**Status as of 2026-10-21:** done, ahead of its dates (November 9 – 22, 2026): all 22 points, in PRs #18 to #29. VLW-21 moved in from Sprint 4 and VLW-22 from Sprint 3. Its counterpart, the API's Sprint 2, is VLA-16, VLA-17, VLA-19, VLA-20, VLA-33, VLA-34 and VLA-36; of those, VLA-17 and VLA-19 had not been reported merged when this sprint closed.

**Order:** planned as VLW-15 and VLW-16, then VLW-30 on top of them, then VLW-18 once the API's nonce exists, then VLW-17, then VLW-28 when VLA-20 and VLA-33 are merged. Built in the order the API delivered: VLW-16, VLW-17, VLW-21 and VLW-22 while it worked, VLW-15 after VLA-15, VLW-28 after VLA-20 and VLA-33, then VLW-18 and VLW-30 after VLA-16.

## Sprint decisions

- **VLW-21 moved in from Sprint 4 and VLW-22 from Sprint 3** (product owner, 2026-10-21). Every remaining Sprint 2 story waits for the API (VLA-15, VLA-16, VLA-20, VLA-33), and these two do not.
- **VLW-28 in three PRs** (product owner, 2026-10-21): 28a the data, 28b the tower, 28c mining. The same day the product owner decided three differences from the artboard. The artboard and DESIGN.md change with the PR that builds each one:
  - **One message when the API is down.** The shell's offline banner says it; the tower keeps the last blocks and its freshness line says it is retrying. The tower's own error card is only for failures the banner does not explain, such as a 500 from `/blocks`, and it shows the API's `detail`.
  - **"Block #n joined the chain."** When polling finds a new block, the toast says this instead of "arrived from another node", because another user of the same node may have mined it.
  - **Two new tokens** for the selected cube's sides, `--color-vl-cube-left-on` and `--color-vl-cube-right-on`, because the artboard's colours had none.
- **VLW-30 in three PRs** (product owner, 2026-10-21): 30a the key in memory, 30b composing and signing, 30c sending. The new page replaces `/transact` only in 30c, so `main` can send transactions throughout. Three defaults were accepted the same day:
  - A key file is `{"public_key", "private_key"}`, the format VLW-31's download will write.
  - "Use an example file" is not built, because it is a design-only affordance.
  - The titles of the 400 errors come from the API's text, and its detail is shown as is.
- **No assets inlined as `data:` URIs** (VLW-22). Vite inlined two small font files, which the Content Security Policy blocked; `build.assetsInlineLimit: 0` keeps the policy strict instead of allowing `data:`.
- **Found for VLW-28.** Without a working API behind `/api`, the old explorer gets HTML instead of blocks, calls `.reduce` on `undefined`, and the whole app goes blank. Nothing catches a render error. The tower must check the shape of `/blocks`, and a route-level error boundary would keep the shell alive when a page fails.

## Retro

- **Went well:** each view landed as soon as the API delivered its data, checked in a real browser against a live API. The API's vectors made signing exact on the first try: the page reproduces the "transfer" vector's signature in a test. AR-05 now proves, with a test that fails on a leak, that the key never leaves the browser.
- **To improve:** 28b (about 610 lines) and 30b (about 400) went over the ~300-line rule; their size should have been estimated in the plan. Twice a staged deletion slipped into the wrong commit; it was caught and fixed before pushing.
- **To try:** estimate each part's size in the plan, and split before writing. Check `git diff --cached` before every commit. Agree on Sprint 3's order with the API's remaining stories (VLA-35, VLA-19) in view.
